# Quality check 2026-11-01

The ten quality rules checked against the code, with evidence. Go 1.26.10, Windows 11, Intel Core
i7-13700H. The simulator is single-threaded and has no network, database or clock of its own; the
real runtime (`realenv`) is the only part that touches sockets, files and the wall clock.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | fixed | External calls are UDP and files in `realenv` (errors returned to the caller; UDP read errors skipped with the reason in a comment, `realenv.go:191`). `kv.Replica.send` ignores `Send` errors on purpose: the protocol resends on timers (`kv.go:301`, comment). Found and fixed: (a) `sim.traceLine` discarded trace-writer errors (`_, _ = s.cfg.Trace.Write`), and `dst run -trace` deferred `Flush`/`Close` without checking them, so a full disk gave a silently truncated trace; now the first error is kept in `Result.TraceErr` and `dst run` exits 2 (`TestTraceWriteErrorIsReported`). (b) `scenario.settled` ignored `rc.Do` errors; on a closed cluster no check ran and the cluster was reported settled. Now an error counts as not settled (`TestClosedClusterIsNotSettled`). The real runtime's wait is bounded by `-timeout`. |
| 2 | Writes safe to retry | pass | Client retries reuse the request number; the primary orders a request once per client session and answers repeats from the session (`kv.go` `onPut`, `TestPrimaryDeduplicatesRetries`). Backups apply each sequence number once (`TestBackupAppliesInSequenceOrder` sends a duplicate and checks one WAL line). |
| 3 | No race conditions | pass | Services run one callback at a time per node (`env` package comment); `realenv` posts every callback to the node's goroutine and node maps are written only before `Start`. `go test -race` needs cgo, which this machine lacks; CI runs `make ci GOTESTFLAGS=-race`. |
| 4 | Don't trust the clock | pass | Simulated time is virtual (`sim.Epoch` plus an offset, UTC). Durations on the host use the monotonic reading of `time.Now`: `scenario.Sweep` (`time.Since`), `RunReal`, `waitFor` (`Before` on monotonic times). No timestamps are stored. |
| 5 | Read before changing | pass | Standard library only; `go vet` clean. No environment variables are read (`git grep Getenv`: none). Every path the README lists exists. |
| 6 | Never break compatibility | pass | Only additions: `sim.Result.TraceErr` (new field) and a stricter `real -timeout` (now (0, 10m]). The golden trace hash of seed 1 is unchanged (`TestGoldenTrace`), so recorded seeds replay as before. |
| 7 | One source of truth | pass | No caches or copies. Go version: `go.mod`, CI `1.26.10`, README "Go 1.26+": consistent. Defaults live in `scenario.Default()` and the CLI reads them from there. |
| 8 | Small changes, no secrets, validate input | fixed | Secret scan (`git grep -niE "password|secret|api[_-]?key|token"`): only `go/token`. CLI flags are bounded (`scenario.validate`, `sweep -count`, `replay -runs`); messages are decoded strictly. Found: `dst real -timeout` accepted 0 or negative values, and the target directory was emptied before any check; now refused with exit 2 before anything is deleted, and `scenario.RunReal` refuses the same range (`TestRealRefusesBadTimeoutBeforeEmptyingDir`, `TestRealRuntimeTimeoutIsBounded`). No new dependency. |
| 9 | Tests that can fail | fixed | No tautologies or skips (`git grep -n "t.Skip"`: none). Mutation table below: 13 of 18 killed before, 18 of 18 after; the three mutants of the new fixes are killed too. |
| 10 | Re-verify | pass | `gofmt -l`: no files. `go vet ./...`: clean. `dst lint example/kv`: clean. `go test -count=1 -v ./...`: 47 passed, 0 failed (39 before). `make bench`: correct store 0 of 1,000 seeds failed (561,593 events), seeded bug 288 of 1,000, replay of seed 2 identical 3 of 3, real runtime 120 operations, all as recorded in `docs/results/m1.md` (wall time is higher on a loaded machine; the recorded figure is unchanged). `govulncheck@v1.8.0 ./...`: `No vulnerabilities found.` CI result is recorded in the commit's workflow run. |

## Known limitations

- The race detector runs only in CI (no C compiler on the development machine).
- A `Send` error inside the example store is not counted; the store relies on resends, and lost
  messages are already modelled by the network.
